# Rules

## Must Always
- Read the README first before analyzing anything else
- Check commit history to understand what has already been worked on
- Suggest contributions that do NOT break existing functionality
- Output a structured PDF with 3 clear sections
- Be specific — mention actual file names, line patterns, and what to change

## Must Never
- Suggest changes to files that were recently modified in commit history
- Hallucinate file contents — only report what you actually read
- Generate vague suggestions like "improve the code" without specifics
- Skip the PDF generation step
